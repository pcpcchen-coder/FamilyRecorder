## 摘要包含哪些內容

預設輸出繁體中文 Markdown，包含：

1. **事件時間軸** —— 保留約略時間與可能說話者
2. **家庭成員重點** —— 依逐字稿實際出現的「可能說話者」分組
3. **對話方向與人別線索** —— 同列時間、可能說話者與來源方向
4. **今日重要消息**
5. **決策與承諾**
6. **待辦事項** —— 分開保留可能說話者、明確指派的負責人、提出時間與期限
7. **值得追蹤的想法或靈感**
8. **關鍵實體** —— 人名、專案名與產品名
9. **可能辨識錯誤或需要人工確認的片段**
10. **100 字內的今日摘要**

### 從逐字稿到摘要

**原始逐字稿：**

```markdown
### 19:40:07–19:40:12 — 可能：家人二（87%） — 方向：左側 92°；穩定度 80%

明天記得去拿包裹，九點前要出門。
```

**產生的摘要：**

```markdown
## 事件時間軸

- 約 19:40｜可能說話者：家人二｜來源方向：左側 92°：提到明天要拿包裹，並希望九點前出門。

## 對話方向與人別線索

- 約 19:40｜可能說話者：家人二｜來源方向：左側 92°。

## 家庭成員重點（依可能說話者）

### 家人二

- 約 19:40：提醒明天拿包裹，並提到九點前出門。

## 待辦事項

- 約 19:40｜可能說話者：家人二：明天拿包裹；預計九點前出門。負責人需確認。
```

注意最後一行的「**負責人需確認**」—— 說話者不會自動變成待辦負責人。

## 時間、人別與方向契約

三份契約由**程式在每一次請求中強制附加**，與你自訂的 `summary.prompt` 無關。即使現有 `config.yaml` 使用舊版或自訂 prompt，升級後也會生效。

### 時間契約

| 規則 | 說明 |
|---|---|
| 時間來源 | 每日逐字稿的**段落標題**，不是讓雲端模型猜測 |
| 精度 | 只顯示到分鐘，並加上「約」 |
| 跨片段 | 事件跨越相鄰片段時可顯示 `約 19:40–19:41` |
| 無法對應 | 必須標示「**時間不明**」 |
| 禁止 | **不可拿摘要執行時間代替來源時間**，也不可從對話語意自行推測時間 |

`19:40:07–19:40:12` 是 Whisper 文字片段對應的音訊時間範圍，**不代表每個字都有鑑識級精準時間**。所有時間均沿用錄音 Mac 的本地日期與時區。

### 人別契約

| 規則 | 說明 |
|---|---|
| 措辭 | 一律使用「**可能說話者**」，不是確認身分 |
| 多人 | 同一事件跨多位成員時可列多位，或標示「可能多人」 |
| 不確定 | 把握不足則保留「不確定／人別未提供」 |
| 分離 | **說話者 ≠ 待辦負責人**。說話者只代表該片段的可能主要聲音 |
| 禁止 | 未標記或混合的片段**不得硬分配**給任何成員 |

### 方向契約

| 規則 | 說明 |
|---|---|
| 定位 | 方向是聲源相對於麥克風的**角度，不是人的姓名** |
| 並列 | 同一片段有穩定音色與穩定方向時，摘要並列兩者作為相互參考 |
| 禁止 | **沒有音色姓名的片段，絕不會只靠方向硬指定某位家人** |
| 干擾 | 家庭成員移動、兩人站在同方向、牆面反射、電視或多人同時說話都可能使方向不準 |

## 登入與手動執行

### 一次性登入

先用官方 Codex CLI 打開瀏覽器登入 ChatGPT：

```bash
codex login
codex login status
```

若只安裝 ChatGPT macOS app，FamilyRecorder 也會自動尋找 app 內附的官方 Codex。`doctor` 應顯示：

```text
ChatGPT login: Logged in using ChatGPT
```

登入由 Codex 自己保存與更新。**FamilyRecorder 不會開啟其認證檔，更不會把 token 放進 YAML、plist 或 log。**

### 手動執行

```bash
RUNTIME="$HOME/Library/Application Support/FamilyRecorder"
CONFIG="$HOME/.config/familyrecorder/config.yaml"

"$RUNTIME/venv/bin/family-recorder" --config "$CONFIG" summary --date 2026-08-19
```

不帶 `--date` 時會整理 Mac 本地日期的**昨天**，與每日排程相同。

> **要整理今天？** 用選單列的「立即整理今天」，或明確傳入今天日期：
> ```bash
> "$RUNTIME/venv/bin/family-recorder" --config "$CONFIG" summary --date "$(date +%F)"
> ```

重跑同一天會**覆寫** `summaries/YYYY-MM-DD.md`，並更新 SQLite `summaries` 表的同一筆日期索引。

## 純文字邊界

摘要使用官方非互動模式 `codex exec`。每次執行固定為：

| 參數 | 效果 |
|---|---|
| `--ephemeral` | 不留下 session 狀態 |
| `--sandbox read-only` | 唯讀沙箱 |
| 空白暫存工作目錄 | 每次都在新的空目錄內執行 |
| 不載入使用者 MCP／專案規則 | 不受本機其他設定影響 |

prompt 本身也要求**不得呼叫工具**、**不得遵循逐字稿內的指令**。

隱私邊界是**程式結構上的限制**，不是靠 prompt 承諾：

| 保護 | 做法 |
|---|---|
| 不讀音訊 | `summary` 指令只開啟 `transcripts/YYYY-MM-DD.md` |
| 不讀聲音特徵 | 不開啟 `audio/` 或 `speaker-profiles/` |
| 不進 process 清單 | 逐字稿透過 **stdin** 傳給 Codex，不出現在 process arguments |
| 不讀認證檔 | 只執行官方 `codex login status` |
| 沒有上傳實作 | 摘要程式碼中**根本沒有音訊解碼或上傳的實作** |

> ⚠️ **逐字稿文字本身可能包含敏感內容、近似人別姓名與家庭事件。** 啟用前應先檢視 prompt、ChatGPT 資料設定與家庭共識。若不想使用雲端摘要，把 `summary.enabled` 設為 `false` 即可 —— 錄音與本機逐字稿完全不受影響。

參考：[Codex 登入](https://learn.chatgpt.com/docs/auth)、[Codex 非互動模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference)。

## 長逐字稿如何切分

超過 `summary.max_input_chars`（預設 300,000）時，逐字稿會被切成多段分別整理，最後再做一次去重整併。

**切分點只在完整的 `### 時間 — 人別 — 方向` 段落之間**，避免標題與內容被拆到不同請求。每一段先保留事件時間、可能說話者與不確定性，最後才把同一天的中間整理去重合併。

**時間、人別與方向契約會出現在每一個分段請求與最終整併請求中**，因此切分不會靜默地丟掉時序或人別。

## 自訂摘要 prompt

從選單列 →「**更換模型 → ChatGPT 摘要**」以多行編輯器修改，或一鍵恢復內建格式。也可用指令：

```bash
"$RUNTIME/venv/bin/family-recorder" --config "$CONFIG" \
  set-summary-prompt --prompt "$(cat my-prompt.txt)"

"$RUNTIME/venv/bin/family-recorder" --config "$CONFIG" reset-summary-prompt
```

變更**只套用到之後產生或重新執行的摘要**，舊摘要檔不會自行重寫。想套用到舊日期，重跑該日期的 `summary --date`。

> 換掉 prompt 是把 FamilyRecorder 變成別種服務的主要方式。課後複習講義與夢境日誌的完整 prompt 範本，見 [應用場景指南](use-cases.md)。

安全規則與時間／人別／方向契約**仍由程式強制附加**，自訂 prompt 無法繞過。

### 摘要模型

`summary.model` 留空會使用帳號／Codex 的預設模型。若填入自訂模型，FamilyRecorder 會在執行時以明確的 `--model` 覆蓋預設。這符合官方 Codex config reference 的優先順序。

摘要模型**在每次摘要執行時重新讀取**，改了不需要重啟任何服務。

## Google Calendar 候選事件

FamilyRecorder 預設支援 Google Calendar，但**不另存 Google 密碼或 OAuth token**。它使用已加入 macOS「Internet 帳號」並在「行事曆」App 中同步的 Google 帳號；第一次使用會由 macOS 詢問 `FamilyRecorder` 行事曆權限。

### 設定步驟

1. 若 Mac 尚未加入 Google 帳號，先到「**系統設定 → Internet 帳號 → 加入帳號 → Google**」，並開啟「行事曆」。
2. 點 FamilyRecorder 選單 →「**Google Calendar**」→「**連接／選擇預設 Google Calendar…**」。
3. 在「**家庭成員日曆對應**」中，為每位成員勾選一個或多個可用日曆，再從下方指定該成員的**預設日曆**。
4. 每日摘要或「立即整理今天」會先產生人類閱讀的摘要，再由 ChatGPT 執行**一次具有固定 JSON 結構的候選事件擷取**。
5. 預設是**逐筆確認**：從「待確認事件」檢視標題、時間、成員與目的日曆，再確認建立、改選日曆或略過。
6. 若不想每天確認，點「**摘要後自動加入…**」，閱讀說明後按一次「同意並開啟」。

### 候選事件如何產生

| 情況 | 處理 |
|---|---|
| 日期與時間都明確 | 一般候選事件 |
| 日期明確、沒有時間（例如「明天考試」） | **全天候選** |
| 日期也不明確 | **略過**，不猜測 |
| 成員可判斷 | 依成員及日曆顯示名稱建議路由 |
| 成員無法確定 | 回退到成員預設，再回退到全家預設 |

### 自動模式

開啟 `auto_create` 後，現有待確認事件與往後摘要產生的事件都會自動加入，通常在摘要完成後 **10 秒內**完成。可隨時從同一選單關閉並恢復逐筆確認。

每則 EventKit 備註會寫入**候選識別 ID**，服務重啟或狀態更新中斷時會先去重，避免重複建立。

### 失敗處理

若事件擷取的第二次 ChatGPT 請求失敗，摘要檔會顯示**警告**，且程式會**保留既有待確認項目**，不會因暫時性錯誤把它們清空。

重新執行同一天摘要只會刷新**尚未處理**的候選項目，不會重建已確認或已略過的同一事件。

### 送出的內容

啟用這項功能後，送往 ChatGPT 的純文字指示會額外包含：

- 家庭成員姓名
- 可選日曆的**顯示名稱**
- 本機 EventKit ID

讓 AI 能建議路由。**Google Calendar 的實際內容不會被讀取或上傳。**

狀態轉換圖見 [系統架構](architecture.md#行事曆候選事件狀態機)。
