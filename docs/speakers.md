# 家庭成員與方向

[English](speakers.en.md) · **繁體中文** · [返回文件索引](README.md)

FamilyRecorder 用**兩份互相獨立的證據**回答「這段話可能是誰說的」：本機音色近似，以及硬體回報的聲源方向。兩者並列呈現，**不會互相取代**。

> ⚠️ 這**不是**身分驗證。這項功能不能用於門禁、付款、家長監護，或任何需要確認身分的用途。

## 這個功能在做什麼

這項功能特別針對「**少數、固定、已知**的家庭成員」設計，不是泛用語者分離或身分驗證。

| | 它能做 | 它不能做 |
|---|---|---|
| **音色** | 判斷這段聲音**像不像**某位已註冊成員 | 確認身分、逐字聲紋鑑識、辨識未註冊的人 |
| **方向** | 指出聲源相對麥克風的**角度** | 判斷是誰、距離、房間座標 |

Whisper 完成一個 30 秒 chunk 後，系統會使用其 JSON 時間戳拆成**通常數秒長**的文字片段，再對各片段的音訊範圍分別比較音色、頻譜與音高特徵。這比「整個 30 秒只標一人」細緻得多，但仍是「Whisper 片段級」而不是逐字聲紋鑑識 —— **錯認仍然可能發生**。

## 註冊家庭成員

### 從選單列（建議）

1. 點選單列 FamilyRecorder →「**家庭成員與人聲**」→「**設定家庭成員…**」。
2. 每行輸入一位成員。**姓名只進入這台 Mac 的私人 YAML**，不必寫進公開 repo。
3. 逐一點選成員 →「**錄製聲音樣本…**」。
4. 第一次使用時，依 macOS 提示允許 FamilyRecorder 使用麥克風。
5. 按下開始後，浮動視窗會在倒數與 15 秒錄音期間持續顯示朗讀範例、剩餘時間及目前狀態。**錄音服務會自動暫停，完成後自動恢復。**

### 從指令列

listener 執行時**必須先暫停**，否則麥克風被佔用：

```bash
RUNTIME="$HOME/Library/Application Support/FamilyRecorder"
CONFIG="$HOME/.config/familyrecorder/config.yaml"
FR="$RUNTIME/venv/bin/family-recorder"

"$FR" --config "$CONFIG" set-speakers --name "我" --name "家人二" --name "家人三"
"$FR" --config "$CONFIG" pause
"$FR" --config "$CONFIG" enroll-speaker --name "我" --seconds 15
"$FR" --config "$CONFIG" resume
```

### 錄製時的建議

| 建議 | 原因 |
|---|---|
| 站在平常說話的位置 | 距離與房間反射會影響特徵 |
| 用自然音量與語速 | 刻意放慢或提高音量會產生不具代表性的特徵 |
| 環境安靜 | 背景人聲或電視會污染特徵 |
| 環境、麥克風位置或聲音明顯改變時重新錄製 | 特徵是相對於錄製當下的條件 |
| **兒童建議定期更新** | 兒童聲音隨成長變化明顯 |

刪除某位成員的樣本：

```bash
"$FR" --config "$CONFIG" delete-speaker-profile --name "家人二"
```

或從選單選「刪除聲音樣本」。刪除只影響該成員，其他人不受影響。

## 判定如何運作

對每一個 Whisper 文字片段：

1. 取出該片段時間範圍內的 PCM。
2. 抽取正規化的**頻譜、音高與時長特徵**向量。
3. 與**已刻意註冊**的本機 profile 做 cosine 相似度比對。
4. 只有以下三項**同時**達標才顯示姓名：

| 條件 | 設定欄位 | 預設 |
|---|---|---:|
| 最高相似度足夠高 | `speakers.min_similarity` | `0.82` |
| 第一名領先第二名足夠多 | `speakers.min_margin` | `0.025` |
| 片段內足夠比例的分析視窗同意 | `speakers.dominance_threshold` | `0.65` |

### 結果狀態

| `speaker_status` | 逐字稿顯示 | 意義 |
|---|---|---|
| `recognized` | `可能：某人（87%）` | 三項條件都達標 |
| `mixed` | `可能多人` | 多人同時說話，或分析視窗意見分歧 |
| `uncertain` | `不確定` | 相似度、差距或一致性任一不足 |
| `disabled` | 不顯示 | `speakers.enabled` 為 `false` |

`speaker_confidence` 是**本機特徵相似度**，不是統計校準後的身分機率。87% 不代表「有 87% 的機率是這個人」。

多人同時說話、電視、距離過遠或把握不足時，會標「可能多人」或「不確定」—— **這是刻意保守的設計**。

## 方向如何與音色並列

XVF3800 透過獨立的 USB control 介面回報 DoA 角度。方向與音色被當成**同一時間片段的兩項獨立證據**並列，而不是用座位直接綁定姓名。

```markdown
### 19:40:07–19:40:12 — 可能：爸爸（87%） — 方向：左側 92°；穩定度 80%

明天記得去拿包裹。
```

### 為什麼要並列

| 情況 | 結果 |
|---|---|
| 爸爸移到別的位置 | **姓名仍由音色判斷**，方向跟著新的聲源位置改變 |
| 兩人坐在相同方位 | 方向無法分辨兩人，音色仍可能可以 |
| 兩個明顯方向 | 標示「方向：多個」，不收斂成主要說話者 |
| 音色與方向衝突 | 摘要會保守標示需人工確認 |
| 沒有音色姓名 | **絕不會只靠方向指定某位家人** |

方向可以佐證音色，也能揭露同一個 30 秒 chunk 內的人員變動 —— 但**方向不能把位置對應到人**。

### 干擾因素

牆面反射、電視、喇叭回音、多人同時說話，或兩人位於相同方位，都可能讓 DoA 不準。**方向是輔助線索，不是人別或距離感測器。**

方向校準與測試見 [硬體與收音 → 方向校準](hardware.md#方向校準)。

## 調校門檻

| 症狀 | 怎麼調 |
|---|---|
| **常常認錯人** | 提高 `min_similarity`（例如 `0.86`）或 `min_margin`（例如 `0.04`） |
| **大多顯示「不確定」** | 才**小幅**降低 `min_similarity`（例如 `0.79`）。先確認樣本品質 |
| **常顯示「可能多人」** | 提高 `dominance_threshold` 會更嚴格；通常真正的原因是環境有多人或電視 |

調整前，先做這幾件事往往更有效：

1. 讓每位成員在**相同麥克風位置**重新錄製自然語音。
2. 避免電視、音樂與多人同時說話的環境。
3. 用 [placement test](hardware.md#mic-placement-test) 確認麥克風位置本身是好的。

**降低門檻會直接增加誤認。** 由於誤認的人名會進入逐字稿與雲端摘要，寧可保守。

改完設定要重啟 listener（選單列的變更會自動處理）。

## 隱私

| 項目 | 做法 |
|---|---|
| **註冊音訊** | 只存在記憶體中，產生特徵後即丟棄。**不會建立 WAV** |
| **特徵檔** | 權限 `0600`，存於 `speaker-profiles/speaker-<雜湊>.json` |
| **可播放性** | 特徵向量**無法還原成聲音** |
| **雲端** | 特徵**永遠不會**送給 Whisper、Codex 或任何雲端服務 |
| **姓名** | 只存在本機 YAML。雲端摘要會收到逐字稿標題中的姓名文字 |
| **刪除** | 刪除成員或選「刪除聲音樣本」會移除對應檔案 |

> ⚠️ 聲音特徵仍屬**敏感個人資料**。它無法還原成聲音，但足以識別是否為同一個人。應保護這台 Mac 的帳號密碼與備份（Time Machine、iCloud 備份都會包含它）。

註冊必須是**刻意的動作** —— 系統不會從日常錄音中自動建立任何人的 profile。未註冊的人永遠是「不確定」。

完整威脅模型見 [隱私與信任邊界](privacy.md)。
