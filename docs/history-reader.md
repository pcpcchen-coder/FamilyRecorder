# 歷史紀錄閱讀頁

[English](history-reader.en.md) · **繁體中文** · [返回文件索引](README.md)

## 怎麼開啟

點選單列 FamilyRecorder 波形圖示 → **閱讀歷史紀錄…**。程式先更新本機閱讀副本，再使用預設瀏覽器開啟，不會啟動錄音、重做摘要、呼叫 ChatGPT 或上傳任何資料。

想放到書籤或自行開啟檔案：選單 → **打開… → 歷史紀錄首頁的位置**，Finder 會選取 `history/index.html`。預設完整位置是 `~/xvf3800-listener-data/history/index.html`，若有自訂 `storage.data_dir` 則跟隨該位置。

## 閱讀方式

- 首頁按摘要來源日期由新到舊排列，每張卡片分開呈現**200 字摘要**與**已加入行事曆**。可選月份、摘要狀態、只看已加入事件的日期，或搜尋**日期、摘要全文與行事曆文字**。
- 「閱讀最新一天」直接開啟最近有資料的日期，不假設今天一定有錄音。
- 點入日期後可切換**200 字摘要／Google Calendar／完整摘要／完整逐字稿**，並前往較早或較新的有紀錄日期。有短摘要時預設先看短摘要；沒有則顯示完整摘要、逐字稿或僅存的行事曆紀錄。
- **頁內尋找**搜尋目前選取的內容；輸入姓名、時間或字詞，按 Enter／「下一筆」跳至下一個符合位置。首頁不搜尋全部逐字稿。
- 可放大字體、列印目前內容，或使用 macOS 列印視窗存成 PDF。頁面跟隨系統深淺色模式。
- 可下載原始 Markdown；閱讀頁不會改寫原本的文字、時間、人別與方向。

「尚無摘要」仍能讀逐字稿。若逐字稿檔案的最後修改時間晚於摘要，會顯示「**逐字稿有新內容**」。這是檔案時間提示，不是內容逐項比對；手動編輯或還原檔案也可能觸發。

### 200 字摘要與行事曆分開看

- 短摘要直接取自原文的「200 字內今日摘要」「今日摘要（200 字內）」等獨立標題，也支援編號／粗體標題與舊的 100 字摘要。不會修改自訂 prompt，亦不會重新呼叫 AI。
- 最多顯示 200 字元；原文較長會標示截短並保留完整摘要。找不到獨立短摘要時，分頁顯示缺少提示，首頁明確標為「完整摘要節錄」，不把節錄冒充新生成的短摘要。
- **Google Calendar** 分頁從本機 SQLite 行事曆紀錄呈現標題、活動起訖時間與時區、全天、相關成員及備註。首頁顯示已加入筆數及前兩筆預覽；不是從摘要文字推測成功與否。
- 「已加入」只計 `created`（App 收到系統 EventKit 寫入成功回覆）。待建立／確認、失敗、略過另外收合顯示，不算入成功筆數；失敗操作若尚未改狀態，仍會列於待建立。
- 日期頁依**產生事件的摘要日期**整理，事件卡另列**實際活動日期**，可能是未來。全天事件的結束日期不包含在活動範圍內。
- 這是**本機寫入快照，不是 Google 雲端即時同步查詢**。後續在日曆編輯／刪除的結果不反映於此；既有資料未保存實際目的日曆名稱，因此不顯示建議日曆為實際目的地。成員欄不是已確認的說話者身分。

## 何時更新

1. 每次成功完成摘要（排程、指定日期或「立即整理今天」）後，自動更新首頁與日期頁。
2. 每次從選單開啟閱讀頁或顯示其位置時，也會更新，讓今天尚未摘要的逐字稿可閱讀。
3. App 成功記錄「事件已建立」或「已略過」後也會更新，因此摘要後自動建立的事件不用等到隔天才出現。
4. 已開啟的瀏覽器頁面是**快照**，不會持續監聽錄音。需最新內容時，再點選單入口並重新整理瀏覽器。單按瀏覽器重新整理不會重新產生 HTML。

不想重跑 AI 摘要，只要更新閱讀頁：

```bash
RUNTIME="$HOME/Library/Application Support/FamilyRecorder"
CONFIG="$HOME/.config/familyrecorder/config.yaml"
"$RUNTIME/venv/bin/family-recorder" --config "$CONFIG" build-history
```

此指令只輸出首頁路徑，`summary.enabled: false` 時也可使用。不需要新增排程或修改設定檔。

## 隱私、檔案與失敗處理

- 只讀 `transcripts/YYYY-MM-DD.md`、`summaries/YYYY-MM-DD.md`，以及 `listener.sqlite3` 的 `calendar_candidates` 白名單文字／狀態欄位。SQLite 使用唯讀連線，不建立或遷移資料庫；不讀 WAV、其他資料表、聲音特徵、登入憑證或外部事件／日曆 ID，也不補入被過濾的辨識結果。
- 沒有資料庫或舊資料庫沒有行事曆資料表時，仍可閱讀；資料庫無法讀取時顯示「暫時無法讀取」，不冒充零事件、不影響摘要與逐字稿。
- `history/` 是可重建的**敏感文字副本**，不是公開網站；資料夾權限 `0700`、檔案 `0600`。不要放進公開網站或不受信任的同步資料夾。
- 不用本機伺服器、外部字型／圖片／套件 CDN、追蹤或網路請求。內容中的 HTML、連結與圖片語法顯示為文字，不會執行或載入。支援標題、粗體、清單、引用、程式碼與簡單表格；其他 Markdown 保留文字形式。
- 只更新有所有權標記的閱讀目錄；若 `history/` 已放了其他檔案或是符號連結，會報錯保留原檔。來源逐字稿和摘要不變。
- 更新以鎖定與單檔原子替換避免同時刷新寫壞；失敗不會丟掉已完成的摘要，也不會重試雲端或行事曆操作。錯誤寫入摘要 log，可用 `build-history` 重試。
- 原始音訊 retention 不刪逐字稿、摘要或閱讀副本。日期的 Markdown **及 SQLite 行事曆來源紀錄皆不存在**時，下次刷新才會移除對應日期頁；只刪 Markdown 仍會保留行事曆內容。資料庫讀取失敗時暫不清理日期頁；已開啟的分頁／下載的副本仍需自行關閉或移除。
- 「完整解除安裝」包含產生的 `history/`；「保留資料」則保留它。不要把自訂檔案放進這個產生目錄。

## 驗收

1. 無紀錄時應看到空狀態；只有逐字稿時也能點入，預設顯示逐字稿。
2. 執行指定日期摘要後，首頁顯示該日期；重跑不增加重複日期。
3. 月份、摘要狀態、摘要字詞篩選可以組合使用；清空搜尋能恢復列表。
4. 日期頁可切換內容、前後日、尋找多個同詞、放大與列印；來源時間／人別／方向保留。
5. 關閉網路後仍可開啟已生成的首頁及日期頁；開啟頁面不觸發錄音或 AI。
6. 測試用 Markdown 放入 `<script>` 或圖片網址，應只顯示文字；不執行或載入網址。
7. 短摘要分頁只顯示該段，不混入後面的行事曆說明；無短摘要不會偷偷呼叫 AI。完整摘要仍可閱讀。
8. 行事曆分頁的成功筆數不包含待建立項目；可看到未來活動日期／時區。完成建立後，重新整理已開啟頁面可見新狀態，不重新建立事件。

程式測試：`pytest tests/test_history.py tests/test_history_data.py tests/test_uninstaller.py`；互動測試：`FR_TEST_PYTHON=.venv/bin/python npm test`（先 `npm ci --ignore-scripts`）。虛構閱讀測試資料位於 `tests/fixtures/history/`，不含家庭真實對話。
